# Autonova Orders Tagger

Chrome-розширення (MV3) для атрибуції замовлень на `autonovad.ua` між співробітниками, які працюють під одним спільним акаунтом (`код клієнта 48320`).

## Що робить

- **Перехоплює оформлення замовлення** на новому checkout'і (`cp.autonovad.ua`) і зберігає у Supabase: хто, коли, на яку суму, з яким товаром.
- **Дорисовує бейдж з іменем** поряд кожного номера ЗК у історії замовлень (`autonovad.ua/index.html?id=27`).
- **Інструменти на сторінці історії** (керуються з попапа, вкладка «Функції», а фільтри — ще й з **плаваючої панелі** праворуч на самій сторінці історії; обидва місця синхронізовані через `chrome.storage`):
  - **Авто-розгортання** — автоматично тисне «Показати все», щоб розкрити деталізацію всіх замовлень (лише в попапі).
  - **Приховування зібраних замовлень** — ховає замовлення, у яких **усі** позиції мають один з обраних статусів (`ЗС` / `ЗО` / `ЗОП`, налаштовується галочками).
  - **Фільтр за іменем співробітника** — показує лише замовлення обраного співробітника.
- **Атрибутує заявки до замовлень** через RPC `claim_order` за пріоритетом:
  1. **За кодами товарів** (item codes) — найнадійніший: коди унікальні, не перетинаються між замовленнями.
  2. **За точною сумою** — fallback якщо коди не співпали.
  3. **За сумою ± 1₴** (tolerance) — на випадок дрібних розбіжностей. Працює лише коли збіг єдиний.
- **Резервує імена за співробітниками** через таблицю `user_registry`. Двоє не можуть одночасно використовувати одне імʼя. Звільнюється автоматично через 30 днів неактивності.
- **Офлайн-черга з ретраями**: якщо Supabase недоступний у момент оформлення — заявка зберігається локально, фоновий alarm раз на 10 хв повторно її надсилає. Через 24 год невдалих спроб переходить у `failedClaims`.
- **Надсилання логів розробнику** — кнопка у вкладці «Діагностика» завантажує локальний `debugLog` у Supabase (`log_uploads`). Адміністратор бачить усі надіслані логи у прихованій вкладці «Адмін».

## Встановлення (developer mode)

1. Розпакуй ZIP у будь-яку папку (наприклад `C:\Tools\autonova-ext\`).
2. У Chrome відкрий `chrome://extensions/`.
3. Увімкни перемикач **"Режим розробника"** у правому верхньому кутку.
4. Натисни **"Завантажити розпаковане"** і вибери папку.
5. Клікни на іконку розширення у тулбарі, введи своє імʼя, обери колір бейджа, натисни **Зберегти**. Якщо імʼя вже зайняте іншим співробітником — побачиш повідомлення, виберіть інше.
6. Зайди на `https://autonovad.ua/` (потрібно щоб у шапці зʼявився блок з `(48320)`) — це підтвердить код клієнта.
7. Готово. Наступне замовлення буде записане у Supabase. У історії замовлень побачиш бейдж з іменем поряд із номером ЗК.

## Архітектура файлів

| Файл | Що робить |
|---|---|
| `manifest.json` | MV3-маніфест: дозволи на storage/alarms, host permissions на `autonovad.ua` і Supabase. |
| `config.js` | Спільний конфіг (Supabase URL/key, regex ЗК, `EXPECTED_CLIENT_CODE`). Підключається і в content scripts, і в SW. |
| `inject.js` | Запускається в **page world** на `autonovad.ua/*`. Патчить `window.fetch` і `XMLHttpRequest`, ловить відповіді з `cp.autonovad.ua/api/v1/orders` (створення замовлення), `/api/profile`, `/pub/v1/basket`. Витягує `basketId`, `orderUuid`, суму, перелік `itemCodes`. Відправляє у content.js через `window.postMessage`. |
| `content.js` | **Isolated world**. Мост між inject.js і background. Детектить код клієнта з `.user-name` старого сайту. На сторінці історії парсить таблицю замовлень (`tr.table-item`): номер, дата, сума, кількість позицій, **коди товарів з розгорнутих рядків деталізації**. Рендерить бейджі (спочатку з локального кешу, потім з відповіді background). Малює **плаваючу панель фільтрів** праворуч і застосовує фільтри (приховування за статусами + за іменем). |
| `background.js` | Service worker. Спілкується з Supabase REST API: `claim_order` RPC, `reserve_user_name`, `ping_user_registry`, вставка `pending_claims`, lookup `orders`. Тримає офлайн-чергу з ретраями (3 спроби з затримкою 0/2/5с) + 10-хвилинний alarm для повторних спроб. |
| `popup.html` / `popup.js` / `popup.css` | UI: ввід імені, вибір кольору, перевірка резервації імені на Supabase, статус (код клієнта, кількість офлайн-заявок), діагностика (скачати/очистити лог). |
| `icons/` + `make_icons.ps1` | Іконки 16/48/128 і скрипт їх генерації (PowerShell з GDI+). |

## Supabase — схема

Реальна схема в БД керується напряму в **Supabase SQL Editor** (там створені всі таблиці, RPC, тригери та RLS-політики). Локальні файли `sql/01..09` наразі не зберігаються в репо — вся міграція/догляд за схемою ведеться через веб-інтерфейс Supabase.

| Таблиця | Призначення |
|---|---|
| `orders` | Підтверджені замовлення з іменем співробітника (PK = `order_number`). Містить `total_sum`, `order_date`, `delivery_name`, `items_count`, `item_codes` (jsonb), `user_color`, `matched_method` (`exact` / `tolerance` / `item-codes`). |
| `pending_claims` | Заявки від розширення на момент оформлення. RPC `claim_order` шукає в цій таблиці підходящу заявку для нового ЗК-номера з історії. |
| `user_registry` | Резервація імен. `install_id` (UUID розширення) → `user_name` + `user_color` + `last_seen_at`. |
| `log_uploads` | Inbox для логів від співробітників. Заповнюється при кліку «Надіслати логи розробнику». `pg_cron` видаляє записи старше 30 днів. |

### Ключові RPC

- **`claim_order(p_order_number, p_client_code, p_sum, p_order_date, p_items_count, p_item_codes)`** — атомарний multi-pass матчинг (item codes → exact sum → ±1 tolerance) з `for update skip locked`.
- **`reserve_user_name(install_id, name, color, client_code)`** — `out_ok=false, out_message='name-taken'` якщо інший активний install займає це імʼя (case-insensitive, trim).
- **`ping_user_registry(install_id)`** — heartbeat, продовжує реєстрацію. Викликається фоновим alarm'ом і після кожного замовлення.

## Діагностика

- **Console на сторінці**: DevTools → вкладка Console → префікси `[ANO]` (content) і `[ANO bg]` (через message).
- **Background-логи**: `chrome://extensions/` → знайди розширення → клікни **Service worker** → відкриється DevTools.
- **Стан в popup'і**: вкладка «Інфо» показує код клієнта (виявлений з DOM) та кількість заявок у офлайн-черзі.
- **Структурований лог**: вкладка «Діагностика» → **Скачати лог (JSON)**. Містить серіалізовану історію подій (вставки claim'ів, виклики RPC, помилки, мережеві ретраї) за останні 7 днів (до 10000 записів).
- **Надіслати логи розробнику** — кнопка у вкладці «Діагностика». Завантажує поточний `debugLog` + `failedClaims` + метадані в Supabase `log_uploads`. Показує ID запису («Надіслано ✓ Саша / #42»), який можна продиктувати розробнику. Тротлінг 30 сек між кліками.

## Admin-режим

Для перегляду надісланих логів у розробника є прихована вкладка **«Адмін»**.

### Активація (один раз):

1. Відкрий попап розширення.
2. Права кнопка в попапі → **«Inspect»** → відкриється DevTools попапу.
3. У вкладці **Console** введи:
   ```js
   chrome.storage.local.set({ adminMode: true })
   ```
4. Закрий і відкрий попап знову — з'явиться вкладка **«Адмін»**.

Там буде список 50 останніх надісланих логів (імʼя співробітника, версія, дата, к-ть записів, розмір, ID). Клік «Скачати JSON» завантажить повний лог як `autonova-log-<імʼя>-<id>.json`.

### Деактивація

```js
chrome.storage.local.remove(['adminMode'])
```

## Версія

Актуальна версія — у `manifest.json`. Оновлення публікуються через Chrome Web Store (нативний auto-update), вручну перезавантажувати не потрібно.

### Історія змін

- **1.0.6**
  - Виправлено втрату **числових артикулів** при парсингу історії (`890173`, `707919350`…) — раніше матчинг по кодах товарів для таких замовлень не працював.
  - Додано логування пропущених заявок у `queueClaim` (`queue-claim-skip-no-user-name`, `queue-claim-skip-client-mismatch`) — замовлення більше не зникають без сліду в лозі.
  - Полегшено debug-лог: повні тіла HTTP-відповідей зберігаються лише для ключових ендпоінтів (orders / basket / profile), решта — лише `url/method/status`. Знімає ризик упертися у квоту `chrome.storage.local` (~10 МБ).
  - Фільтр приховування зроблено **налаштовуваним за статусами** (`ЗС` / `ЗО` / `ЗОП`) — замість жорстко зашитого `ЗС`.
  - Додано **плаваючу панель** праворуч на сторінці історії з фільтрами (приховування + статуси, фільтр за іменем). Синхронізується з попапом через `chrome.storage`.
- **1.0.5** — авто-розгортання історії, приховування зібраних замовлень (усі позиції `ЗС`), фільтр за іменем співробітника.
